亚比蛋孵化收取工具
====================

这个窗口只做三件事：用仓库里现有的直接登录连接游戏、查询蛋列表、在用户确认后孵化并收取。
它不读取 config.json、session.txt、cookie 或密码文件，也不使用代理环境变量。
打开后保持空闲。重新打开不会自动继续。点“停止并收取”后马上不再孵化，
会收取已经可收取的蛋，并在现有时限内等待已提交的蛋就绪后再收取。
只有新的成功 1-8 是空的，才显示“已彻底停止，格子已空”。
超时、断开、格式不对或超过时限仍未就绪时，显示未确认清空，不把格子说成空的。
关闭窗口或断开会停下，蛋留在游戏里。
1-8 没有格子编号，也没有种类编号或蛋名。本机亲手提交过的格子才显示格号，
其余显示未知格位。界面只显示 eggId，不会把 eggId 当成蛋名。
连上后大约每 5 秒只读一次 1-8；运行中的孵化或收取进行时不另开查询。

协议只使用 scripts/auto_hatch.py 里已经写明的字段：
- 17 / 1-8：es[].ei、pmid、st，st=100 才可以收取
- 17 / 1=1：es[].ei
- 17 / 1-4：eggId 和孵化格 id（1、2、3）
- 13 / 1223：loc=4，id=pmid；回执命令是 2223
2223 除了 _cmd 和 id，没有更完整的字段说明。本工具把 id 与这次发送的 pmid 对齐，
再用下一次成功的 1-8 确认该 ei 已经消失。对不上、超时或断开时，记为不确定，不再自动重发。
1-8 回包没有格子编号。本机提交过的格子会一直占着，直到收取被确认，或用户按下“确认格子已空”。
查询超时或 es 不是列表时，结果是未知，不是空列表。程序不会把 1.1 秒当成孵化完成，
而是至少每 1 秒查询一次 1-8，最多查询 60 秒；到时格子仍然占用。

本仓库快照没有 LICENSE 文件。工具是在这个已授权的 fork 里新增的代码，并直接调用同一仓库的
登录和长连接模块。它不把 Vue 或 WPF 加载器再包一层，也不改写 AolaNative。
连接模块会在登录后做仓库里原有的玩家初始化，并按原有 60 秒节奏发送会话心跳。窗口本身不提供战斗、购买或其他脚本。

在 Windows x64 上构建
---------------------
需要 64 位 Windows、Python 3.12 和网络，以便安装 requirements.txt 里的依赖。
在仓库根目录执行：

    powershell -ExecutionPolicy Bypass -File .\build_egg_hatch.ps1

成功时输出 dist\AolaEggHatch.exe。脚本会检查文件以 MZ 开头。
PyInstaller 不能在 Linux 上直接交叉编译。requirements.txt 最后一行是本地项目 “.”；
若打包时安装这个本地项目失败，可以改为只安装 requirements.lock 和 PyInstaller，
再在源码目录执行 python -m PyInstaller --noconfirm --clean egg_hatch.spec。

本次环境实际产出
----------------
在 Linux 上用 Wine 9 运行 Windows CPython 3.12.16（astral-sh install_only，含 Tk 8.6）
和 PyInstaller 6.16.0，生成 dist/AolaEggHatch.exe。
file 与 PE 头：PE32+ GUI，x86-64，machine 0x8664，magic 0x20b，subsystem 2，约 20.7 MB。
官方 python.org 的 amd64 安装包是 32 位引导程序，当前 Wine 前缀缺少 syswow64\ntdll.dll，未能用它安装。
交付的 exe 是 Windows GUI 子系统（PE subsystem 2），不带控制台窗口。
启动时如果没有标准输出，会把启动记录写到 exe 旁的 logs/egg-hatch-startup.log，
界面异常用错误对话框显示，不另开可见的控制台进程。
在这台 Wine 上，窗口版引导程序以前会在 Python 启动前报
“Failed to start embedded python interpreter”；那是 Wine 下无控制台句柄的现象，
不能当成原生 Windows 的结论。原生 Windows 是否弹出控制台，要以 PE 头 subsystem 2 为准，
本次没有在原生 Windows 上启动。没有点击登录，没有连接游戏。

运行
----
双击 exe 后先填账号并点“查询角色”。这一步不发送密码。只有一个角色时自动选中，多个角色时显示昵称和 charId。
再填密码并点“验证登录”。成功后的区服来自这次登录响应。点“连接区服”才会做游戏长连接：
先 Flash TCP，只使用这一条连接。客户端不发送策略文件请求，也不另开第二条套接字。
服务器若主动下发以空字节结束的策略，按每字节最多 2 秒读完；策略不允许该端口就停止。
没有主动下发时，登录仍发在这条已经连上的套接字上。登录包仍是仓库原来的格式。
解析结果同时有 domain 和 h5 端口时才尝试 H5 WebSocket，不会编造地址。
失败日志包含 host、flash 端口、h5 端口、domain 是否为空，以及 svr 字段个数，不写密码、会话或账号。
长连接包使用登录响应里的用户 ID 和会话，不把 charId 放进这个包。
确认对话框点确定后才会发送孵化或收取。密码只留在本次验证请求里，界面会清空密码框。
本机占用记录写在 exe 旁边的 egg-hatch-local-state.json，里面只有蛋编号、格子和阶段。

测试
----
python -m unittest tests.test_egg_hatch_sim
这些测试是模拟的，标题都带 simulated。它们不登录、不连接游戏，也不能证明 exe 能在 Windows 上启动或在游戏里孵化。
